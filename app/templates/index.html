写锁演练（SQLite 被其他连接占用）

点“开始持锁”后，另一条连接会对同一 SQLite 持有写锁（模拟备份等离线作业占库）。 持锁期间：首页、/healthz 与旧目录下载照常，1 秒内返回已提交内容； 采集写库忙等 {{ busy_timeout_s }} 秒，超时后该页整体回滚——分页进度与发布水位都不推进， 本轮转为“已暂停·可续采”（错误 database_locked），锁释放后点“继续采集”即可， 重读不会产生重复记录。

  1. 持锁与超时：开始持锁（≥45 秒）→ 在锁释放前“开始采集”或“继续采集”： 写库忙等 {{ busy_timeout_s }} 秒后超时，本轮显示 database_locked 并暂停； 锁释放后再点“继续采集”即可完成本轮。 若以 PAGE_DELAY_MS=2000 启动，可在“采集中”途中施加写锁，观察整页回滚。
  2. 写库等待中停机：持锁期间执行 docker compose stop catalog-web： 服务会等写库提交/回滚结束、关闭连接后才退出； docker compose start catalog-web 后本轮变为“已暂停·可续采”，点“继续采集”即可。

演示脚本

  1. 首次“开始采集”→ 全量 5 条并发布；水位 = 本轮截止日。
  2. 在演示源修改/撤回记录（同日 datestamp），再次采集：窗口从水位（含当天）开始，按 identifier 更新或删除。
  3. 采集中点源页面“让所有分页凭据失效”，继续采集会收到 badResumptionToken：从原窗口第一页重采、水位不动、已入库记录不丢。
  4. 选 crash_after_publish 并重采一轮 → 进程退出；docker compose restart catalog-web 后，页面水位与下载文件仍是上一版完整结果。
  5. 用上方“写锁演练”持锁 ≥45 秒，期间首页/下载照常；采集写库超时后本轮暂停为 database_locked，解锁后“继续采集”即可，记录不重复。
